## 2. データ契約

### 2.1 共通キー
- **社内製番 `product_no`**（例: `CRO261001-3`）。ERP が親で、**案件・製番は ERP で1回だけ登録**（品目の製番は空欄で自動採番）。名前・意味を変える前に、ハブの意思決定ログで決める（CLAUDE.md §3-5）。
- 案件番号は `CRO2610xx`、納品書番号 `DN2610-0001`、請求書番号 `INV2610-0001`（年月入りの連番）。

### 2.2 ERP が読む項目（受注システムの `doGet` が返す受注JSON）
ERP は受注システムへ**書き込まない**（Drive 全件上書き方式との競合を避けるため）。同期ボタン（案件タブ）→ Edge Function `juchu-sync` が、次を読む。

| 受注側の項目 | ERP での保存先 | 備考 |
|---|---|---|
| `items[].productNo` | 照合キー（`project_items.product_no`） | 一致した品目だけ更新 |
| `isCompleted` | `project_items.juchu_completed_at` | 完了のとき |
| `completedAt` | 同上 | ISO8601。無いまま完了のときは 1970 年で保存し、画面では「加工完了」と表示 |
| `shippedDate` | `project_items.juchu_shipped_date` | YYYY-MM-DD |
| （同期した時刻） | `project_items.juchu_synced_at` | ERP が記録 |

- 受注 GAS の URL は Supabase の secret `JUCHU_GAS_URL`（コード・ログ・応答に出さない）。
- **要確認**: 完了・出荷の項目が、品目側か受注（親）側か、日時の形式は何か。現状は「品目側を優先し、親側にも対応」という推測で実装している。**実データでの確認が必要**。

### 2.3 ERP が受注システムへ渡す項目
なし（当面は、人が製番で受注システムに登録する。自動連携は次段階）。

## 4. 未決事項（ハブで決める／確認する）

CLAUDE.md §7 と同じ。優先度の高い順:

1. **電子帳簿保存法の運用**: ①総務大臣認定のタイムスタンプ事業者の選定・契約（スキャナ保存は実質必須） ②`docs/事務手続書.md`（案）の【要決定】（責任者・入力担当・期日・受領書類の保存先を Box とシステムのどちらにするか・バックアップ）の確定と税理士の確認 ③事務処理規程の要否、業務処理サイクル方式を使うか
2. **税理士への確認**（`docs/税理士への確認メモ.md`）: MF 会計の「証憑添付」の可否、渡すデータの形式（売上・入金の一覧CSVは未実装）、規程・スキャナ保存の考え方
3. **MF クラウドBox**: JIIMA 認証、メール取込の送信元の制限、API の条件。公式ガイド（2026-08-18）ではスキャナ保存・電子取引に対応（古い紹介資料は非対応と記載）。ERP の「受領書類」機能を取り止めるかは、ユーザーの判断
4. **社内製番の採番ルール**: 既存の ARCHAIVE・受注システムの製番（`CRO261001-3` 形式）と一致させるか。ERP の自動採番を正とするか、手入力か
5. **ホスティング先**: リポジトリは public。GitHub Pages（private にすると有料）／Cloudflare Pages／Netlify
6. MF 併用の終わらせ方（ERP の請求書を正式にするか。設定 `erp_invoice_official`）
7. 外注仕入の支払管理の範囲、受注システムの「加工完了 → 納品処理ToDo」と ERP の分納記録のつなぎ方、在宅ワーク管理ダッシュボードが将来 ERP を読むか
8. **飲食料品の税率引下げ（1%）**: 令和9年4月1日〜令和11年3月31日の予定。法案成立を確認してから、画面の「税率」で登録（さかのぼれない）

## 5. 変更点のまとめ（2026-10-30 〜 11-01）

- **DB（マイグレーション16本）**: 基本スキーマ・関数・ビュー・RLS／入金の銀行情報と取消／帳票の発行・固定／複数税率／受領書類とタイムスタンプ／国税庁の一次資料に基づく修正／出力用ビュー／見積→受注→納品→請求の変換／帳票の発行イメージ／送付の流れ（Box・メール）／帳票の宛先／帳票の記載項目
- **Edge Function**: `ai-extract`（メール・注文書PDF → 案件下書き）、`juchu-sync`（受注の進捗の読み取り）、`timestamp`（RFC 3161。認定事業者は未契約のため保留）
- **画面**: ログイン、ダッシュボード、見積・案件・納品・請求・入金、帳票（発行・固定・印刷・PDF・送付・交付記録）、受領書類、出力（CSV／ZIP、SHA-256照合）、マスタ、税率、設定、受注同期
- **書類**: システム概要書、仕様書 v2.1、操作マニュアル、事務手続書（案）、電帳法対応方針、システム関係書類一覧、タイムスタンプ事業者の比較、税理士への確認メモ
- **自動化**: GitHub Actions の CI（DBの業務シナリオテスト91項目、単体テスト26件、型チェック・ビルド）は GitHub 上で合格。休止防止（毎日 ping）と手動デプロイは設定待ち
