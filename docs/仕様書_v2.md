## 2. 業務フロー

```
見積（案件登録・品目入力 / AI取込で下書き）
  ↓  見積書を発行（内容を固定）→ 印刷・PDF保存 → 交付を記録
受注（status=ordered、客先注文番号）
  ↓  製番ごとに受注・生産管理システムへ（加工現場）
加工 ── 受注システムの「加工完了」を、製番で読み取り同期
  ↓
分納（納品を記録 → 納品書を発行。超過納品はDBが拒否。納品日時点の税率を固定）
  ↓                    ※見積書の画面のボタンで、そのまま全数納品 → 納品書（§2.2）
請求書の作成（次のいずれか。同じ納品を二重に請求することはDBが拒否）
  ・締め請求：得意先の締め日で、複数案件の未請求の納品をまとめる
  ・案件単位：その案件の未請求の納品をまとめる   ・納品単位：1回の納品を1枚にする
  ↓  MF併用中は、MFで正式発行し、番号を控える。ERPの請求書は控え・社内用
入金（入金登録 → 自動消込 → 未回収残高・期日超過）

受け取った書類（請求書・領収書など）→ 受領書類として登録（電子データ／紙のスキャン）→ タイムスタンプ
```

### 2.1.1 画面の構成（レイアウト）
- **左にメニュー（固定幅）、右の内容は画面の残りの幅いっぱい**。ページを切り替えても、内容の幅は変わらない（縦のスクロールバーの有無でも動かない）。メニューは、売上（見積・案件・納品・請求・入金）、書類（帳票・受領書類・出力）、マスタ（得意先・外注先・税率）の順。
- **帳票を作る画面は、左右2列**（幅が約1200px以上のとき。狭いときは縦に並ぶ）。**左が入力・操作、右が帳票の発行イメージ**で、スクロールしても右は見え続ける。
  - 案件：右に、見積書と、各納品書の発行イメージ（タブで切替）。「発行して固定・表示」で、その帳票を発行できる
  - 請求の詳細：右に、請求書の発行イメージ（下書きでも表示）
  - 帳票の詳細：右に、固定した帳票。「印刷 / PDFとして保存」は、帳票だけを印刷する
- **発行イメージ**は、A4サイズ（実際の帳票と同じ見た目）を、置かれた幅に合わせて縮小して表示する。内容は **DB が作る**（`preview_document`。保存せず、いま発行したらこうなる内容）。**保存済みの内容**が対象で、保存・変換・納品のたびに更新される。**発行イメージは、発行（内容の固定）をするまでは、帳票ではない**（「発行イメージ（未発行）」と表示）。
- PDF：現在は、ブラウザの「PDFとして保存」（印刷）で作る。サーバー側でのPDF生成は未実装。

### 2.2 見積書から、そのまま納品書・請求書へ（変換）
案件の画面の上部に「変換パネル」がある。**保存済みの内容**で変換する（金額・税の計算はDB）。

| 手順 | ボタン | 動き（DBの関数） |
|---|---|---|
| ① 見積書 | 見積書を発行・表示 | 内容を固定して発行（`issue_document`）。版・交付記録は§14 |
| ② 受注 | 受注にする | 見積中 → 受注。受注日（未設定なら今日）・客先注文番号を設定（`order_project`）。品目がなければ不可 |
| ③ 納品書 | 納品書にする（残りを全数納品） | **残りの全数量**を、指定した納品日（既定は今日）で納品として記録し（`deliver_all`）、納品書を発行して表示する。**見積中のまま押すと自動で受注になる**。失注・完了の案件、すべて納品済みの案件は不可 |
| ④ 請求書 | 請求書にする（未請求の納品をまとめて） | その案件の未請求の納品を、1枚の請求書（下書き）にして、請求書の画面を開く（`create_invoice_for_project`） |

- **分納**：数量や日付を変えて納品するときは、案件画面の「分納」で記録する（従来どおり）。残りの全数量は、あとから③で納品できる。
- **請求書の作り方（3種）**：①締め請求（得意先×締め日。複数案件をまとめる。「請求」タブ）、②案件単位（④）、③納品単位（「納品」タブの「この納品を請求」。`create_invoice_for_delivery`）。請求書には `kind`（closing / project / delivery）が記録される。
- **請求済みの納品は、どの方法でも二重に請求されない**。得意先が「全数完納」の設定のときは、**案件の全品目を納品するまで、案件・納品単位でも請求できない**（締め請求と同じ規則）。取消した納品は請求できない。請求書を取り消せば、その納品は請求し直せる。
- 案件・納品単位の請求書の対象期間は、含まれる納品の最初の日〜最後の日。締め請求の「期間の開始」（前回の締め請求の締め日の翌日）には影響しない。
- 請求書は下書きで作られる。内容を確認して、「請求」タブの詳細で「発行済みにする」（MFの番号を控える）。

## 3. マスタ

### 3.1 スタッフ
- Supabase Auth のユーザーに紐づく（`staff.id = auth.users.id`）
- 権限：`admin`（すべて。税率の変更、スタッフ・自社情報の変更、操作ログの閲覧）/ `office`（業務データ・帳票・受領書類の登録・更新）/ `viewer`（閲覧のみ）
- 操作者コード `worker_code`：`home` / `matsuda` / `other`（受注システム・在宅ダッシュボードと共通）
- スタッフ未登録のログインユーザーは、業務データに触れない

### 3.2 得意先
- 基本情報、インボイス登録番号（`T`＋13桁）
- 締め日：都度 / 5 / 10 / 15 / 20 / 25 / 末日
- 支払条件：当月・翌月・翌々月 × 当日 / 5 / 10 / 15 / 20 / 25 / 末日
- 計上基準：
  - `都度納品`：分納のたびに請求対象
  - `全数完納`：案件の全品目が納品済みになってから請求対象
- メール宛先：請求書用 TO / CC、納品書用 TO / CC
- **帳票の宛先**：郵便番号・住所・担当部署名・担当者名（「様」は自動付与）。項目ごとに帳票へ「表示する／しない」を選べる（既定は表示）。マスタが既定で、帳票ごと・案件ごとに変更できる（§14）
- 削除しない。取引終了は `active` を外す

### 3.3 外注先
- 名称、担当者、連絡先、締め日、対応工程（表面処理・熱処理・追加工など）

### 3.4 自社情報（`company_settings`）
- 会社名、登録番号、住所、TEL、メール、**振込先**、**端数処理**（切捨て/四捨五入/切上げ）
- **ERPの請求書を正式な請求書として扱うか**（`erp_invoice_official`）。当面は `false`（MFが正式で、ERPは控え・社内用）。POC完了後に `true` にして移行する想定
- 税率は、この表ではなく税率マスタで持つ（§13）。`company_settings.tax_rate` は使わない

## 4. 案件と品目

- 案件番号：自動採番 `CRO` + 年月4桁 + 連番2桁（例: `CRO261001`）
- 品目の社内製番：未入力なら `案件番号-行番号`（例: `CRO261001-3`）。既存の製番を手入力することも可 ※要確認（CLAUDE.md §7）
- 品目：品名、仕様、客先品番、外注先（空欄 = 自社加工）、数量、単位、買単価（原価）、売単価、納期、**税区分**（標準税率・軽減税率など。税率は納品日の時点で決まる）
- 備考（帳票に印字）と、社内メモ（帳票に出さない）を分ける
- 粗利 = 売上（数量×売単価）− 原価（数量×買単価）。外注仕入の実額は別途集計
- 金額は、画面で計算せず、保存後にDBの値を表示する

---

## 5. 分納と納品書

- 品目ごとに「今回の数量」を入力して記録 → 納品番号 `DN2610-0001` を採番
- 単価と、**税区分・税率は納品時点で固定**（後で品目の単価や税率を直しても、過去の納品・請求は変わらない）
- 受注数量を超える納品、受注数量を納品済み数量より減らす変更は、DBが拒否する
- 見積中の案件に納品を記録すると、状態が「受注」になる
- 取消は理由必須。請求書に載っている納品は取消できない
- **全数納品**：残りの全数量を一度に納品として記録できる（§2.2。分納とは別に、ボタン一つで）
- 納品書は「帳票の発行」（§14）で出す。「納品」タブで、納品の一覧と請求の状況が分かる

---

## 6. 請求

- 請求番号 `INV2610-0001`
- **締め請求**：作成時に、締め日（期間末）までの未請求の納品行を集める。期間の開始は「前回の締め請求の締め日の翌日」
- **案件単位・納品単位**の請求書もある（§2.2）。ボタン一つで、その案件・その納品の未請求の行を1枚にする
- 支払期日は、得意先の支払条件から自動計算
- **税率ごとに集計し、消費税は請求書1枚・税率ごとに1回だけ端数処理**（`invoice_tax_summary`）。複数の税率が混在してもよい
- 状態：下書き → 発行 → （取消）。入金消込済みの請求は取消できない（先に入金を取り消す）
- MF併用中：MFで正式に発行し、`mf_invoice_no` に番号を控える。ERPの請求書は「控え・社内用」と明記して出す（§14）
- 請求書の記載事項（適格請求書）：発行者の名称・登録番号、取引年月日、取引内容（軽減税率対象は※）、税率ごとの対象額・適用税率・消費税額、交付を受ける事業者の名称

---

## 7. 入金

- 入金日、入金額、先方が差し引いた振込手数料、方法（振込・現金・相殺・その他）
- **銀行振込は、入金銀行と口座番号が必須**（DBが確認）
- 消込額 = 入金額 + 手数料。期日の古い発行済み請求から順に充当
- 余りは「未消込の入金（過入金・前受）」として得意先残高に表示
- **取消**：理由必須。入金の行は残り、消込が外れて請求書の残高が元に戻る。二重取消は不可

## 8. ダッシュボード

| 指標 | 定義 |
|---|---|
| 総受注額 | 受注・完了の案件の売上合計 |
| 総粗利 | 同、粗利合計 |
| 粗利率 | 総粗利 ÷ 総売上（加重平均）。単純平均は参考 |
| 見積中の金額 | 見積状態の案件の売上合計 |
| 未請求額 | 納品済みで、まだ請求していない金額 |
| 未回収残高 | 発行済み請求の残高合計（取消済みの入金による消込は除く） |
| 期日超過額 | 支払期日を過ぎた残高 |

## 9. AI機能（Sonnet / Haiku）

| 機能 | 入力 | 出力 | 既定モデル |
|---|---|---|---|
| 見積依頼の取込 | メール本文の貼り付け | 得意先候補、品目（品名・数量・材質・板厚・納期）、備考 | Haiku |
| 注文書の取込 | 注文書PDF | 客先注文番号、品目、数量、単価、納期 | Sonnet（PDF・表の読み取り） |

運用ルール：
- AIの結果は**下書き**。人が画面で確認・修正してから保存する（案件画面の「AIで取込」。入力欄に下書きとして入る）
- 得意先は、既存マスタとの照合候補を出すだけ（自動で新規作成しない）
- 1回ごとにモデル名・トークン数を `ai_extractions` に記録。月の上限（`AI_MONTHLY_TOKEN_LIMIT`）を超えたら停止
- APIキーは Supabase の secret に保存し、画面（ブラウザ）には渡さない
- モデルIDは環境変数で指定し、新モデルへの切替をコード変更なしで行う

## 13. 税区分と税率

- **税区分**（`tax_categories`）：標準税率、軽減税率（飲食料品）、軽減税率（新聞の定期購読）。管理者が追加できる。軽減税率の区分は、帳票の明細に※を付ける
- **期間つき税率**（`tax_rate_periods`）：区分ごとに、適用開始日・終了日と税率を持つ。**法改正による税率の変更は、画面「税率」から登録する（コードの変更は不要）**
- 品目が税区分を持ち、納品を記録した日の税率を、納品行に固定する。税率が登録されていない日付の納品は拒否する
- 請求書は税率ごとに集計し、税率ごとに1回だけ端数処理する。見積書は、見積日時点の税率で計算する
- 守り：管理者のみ変更可。その日以降の納品がすでにある税区分は、さかのぼって変更できない。適用期間の重複は不可
- **飲食料品の税率引下げ**：国税庁の令和8年9月の資料では、令和9年（2027年）4月1日から令和11年（2029年）3月31日まで1%。ただし「法案が成立した場合」の内容で、**成立を確認してから登録する**（登録手順と経過措置は `電帳法対応方針.md` §7）。現在は未登録
- 状況：✓（`20261101000007`）

## 14. 帳票の発行・固定・交付

- **宛先（住所・担当部署・担当者）**：得意先マスタの値が既定。帳票の画面の「宛先」から、項目ごとに表示する／しないと値を変更できる。保存先は ①この帳票だけ ②この案件の見積書・納品書・請求書すべて ③得意先マスタにも反映。納品書・請求書は、案件の見積書の設定を引き継ぐ（請求書は、1案件の納品だけを含む場合）。「この帳票の変更をやめる」でマスタ（または案件の設定）に戻せる。非表示にした項目は値を残したまま印刷されない。発行済みの帳票は変わらず、再発行すると新しい版になる（実装 ✓。`resolve_addressee`、`doc_addressees`）
- 見積書・納品書・請求書は、画面の「発行・表示」から出す（ブラウザで画面を直接印刷しない）。DBの `issue_document` が、金額・消費税を計算し、**記載内容を固定**して保存する（`issued_documents`）
- 同じ内容なら既存の版を開き、内容が変わっていれば新しい版を作る（旧版は残る）。内容のSHA-256をDBが記録する
- 表示・印刷は、**固定した内容から**描画する（元データが後で変わっても、発行時の帳票が再現される）。自社情報（住所・登録番号など）も発行時点のものを固定する
- 元の請求書・納品が取消されたら、固定済みの帳票も取消になる（行は残る）
- **PDFの生成**：固定した内容から、A4のPDF（日本語フォントを埋め込んだテキストPDF）をこのシステムで作る。**同じ内容なら、いつ作っても同じバイト列**（日時は発行日時、乱数は固定）。ファイル名は「取引年月日_取引金額_取引先_帳票番号_v版.pdf」。ひな形を変えたら `PDF_TEMPLATE_VERSION` を上げる。フォントにない文字は「?」で出力し、画面で知らせる。
- **送付の手順（案A、2026-11-01 決定）**：帳票の詳細画面で ①PDFをダウンロード → ②お客様宛にメール（PDFを添付）→ ③**Box宛に別のメール**（同じPDFを添付。MF クラウドBox の「メール取込」は、宛先に複数のアドレスが含まれると保存できないため、お客様宛とは分ける）→ ④交付を記録。
- **交付の記録**：紙／PDF（メール）／Box保存／その他、交付日、宛先を、追記のみで残す。「PDF（メール）」を記録すると、**このシステムが作ったPDFを、送付したPDFとして保存**する（別のPDFを送った場合のみ、そのファイルを選べる。サイズ5MBまで。ハッシュをDBが記録）。「Box にも保存した」にチェックすると、Box保存の記録も同時に残す。タイムスタンプは、設定で自社付与をオンにしているときだけ依頼する
- 請求書：MFが正式な間は「【ERP控え・社内用】」「（控え）」と明記し、MFの請求書番号を併記する（`erp_invoice_official`）
- 手書きで加筆して渡した控えは、電子データでは足りず、紙で保存する（運用）
- 状況：✓（`20261031000006`）。ひな形（見た目）を変えたときのバージョン管理は未実装

## 15. 受領書類（電子取引・スキャナ保存）

- **電子取引**：電子データで受け取った書類（メール・Web・EDI等）を、そのまま登録する（再入力は不可）。受け取った方法を必須とする
- **スキャナ保存**：紙の書類を読み取って登録する。DBが読取条件を確認する
  - 解像度 200dpi以上、PDF・PNG・JPEG・TIFF
  - 重要書類（契約書・納品書・請求書・領収書など）は**カラー**、一般書類（見積書・注文書）はグレースケールも可
  - 読取日が授受日より前、または未来でないこと
- **入力期限**：授受日から7営業日（早期入力）、授受日の暦の2か月後から7営業日（業務処理サイクル。事務処理規程が必要）。営業日は土日のみ除外。重要書類で期限を過ぎたものは「紙の原本を保存」と表示。一般書類は入力期間の制限なし
- **帳簿との紐づけ**：重要書類は、登録後に追記で紐づける（未紐づけを一覧に表示。追記のみ）
- 登録後は更新・削除ができない。誤りは取消（理由必須）して登録し直す。同じファイルの二重登録は拒否
- 検索項目：取引年月日、取引金額（税込）、取引先、書類の種類、保存の種類
- 状況：✓（`20261101000008`・`09`）。外注仕入への紐づけ画面、メール添付の自動取込、画像の実解像度の自動測定は未実装

## 16. タイムスタンプ

- 受領書類と送付PDFのSHA-256を、時刻認証局（TSA）へ送り、RFC 3161 のトークンを保存する（Edge Function `timestamp`。追記のみ）。登録・保存のたびに自動で依頼する
- 付与の期限：授受日（送付PDFは送付日）の暦の2か月後から7営業日以内。状況（付与済み・付与待ち・期限超過）を「受領書類」タブに表示し、再実行できる
- 再検証：`scripts/verify_timestamp.sh`（OpenSSL）
- 法令上は、**総務大臣が認定する時刻認証業務**のタイムスタンプが必要。**事業者は未契約**のため、設定（`TSA_URL` など）が入るまで付与は保留（`タイムスタンプ事業者の比較.md`）

## 17. 検索とダウンロード

- 帳票・受領書類は、取引年月日（範囲）・取引金額（範囲）・取引先の組合せで検索できる（電子帳簿保存法の検索要件）
- **ダウンロードの求めへの出力**（画面「出力」、`20261101000010`）：形式・並び順は問われないが、税務職員が確認可能で通常出力できる形式であること（国税庁 電子取引 問59）。
  - 取引年月日の期間を指定し、取消済みを含めるかを選ぶ（既定は含める。取消の有無・理由が列に出る）
  - **一覧CSV（3種）**：受領書類、発行済み帳票（交付の記録つき）、送付PDF。取引年月日・取引金額・取引先、SHA-256、タイムスタンプの状況などを含む。UTF-8（BOM付き）・CRLFでExcelで開ける。セルが `= + - @` で始まる文字列は、式として実行されないよう先頭に `'` を付ける
  - **ZIP（一式）**：3つのCSV、受領書類・送付PDFのファイル本体、**発行済み帳票**（版ごとに、固定した内容の `.json` と、ブラウザで開ける単体の `.html`）、README。ファイル名は「取引年月日_取引金額_取引先_…」の規則性のある名前。`.json` はハッシュの計算に使った文字列そのもので、SHA-256が一覧CSVの値と一致する。ダウンロードしたファイルと帳票の固定内容のSHA-256を、記録した値と照合してREADMEに書く（一致しないものは列挙する）
  - ファイルの合計が300MBを超える場合は、期間を分けて出力する
- 基準期間の売上高5,000万円以下などの場合は、ダウンロードの求めに応じられれば、検索要件（範囲指定・組合せ）は不要
