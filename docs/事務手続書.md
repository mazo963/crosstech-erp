# 事務手続書（国税関係書類に係る電子計算機処理に関する事務の手続を明らかにした書類）【案】

作成: 2026-11-01（**案。運用を決めてから確定する**）
備付け書類の区分: 電子帳簿保存法施行規則第2条第2項第1号ニ（入出力処理の手順・日程・担当部署、電磁的記録の保存等の手順・担当部署）
関連: 操作の具体は `docs/操作マニュアル.md`、システムの構成は `docs/システム概要書.md`、方針と根拠は `docs/電帳法対応方針.md`、書類の一覧は `docs/システム関係書類一覧.md`

**【要決定】**は、会社として決めて書き込む項目です。**案**と書いた期日・担当は、作成者の提案で、決定ではありません。**【決定】**は、2026-11-01 に会社として決めた項目です（回答の解釈に確認が必要なものは【要確認】）。確定前に、顧問税理士の確認を受けてください（`docs/税理士への確認メモ.md`）。国税庁のサンプルの記載との照合は、未実施です。

## 1. 目的と適用範囲

株式会社クロステックが、販売管理システム（以下「システム」）で作成・管理する取引関係書類と、受け取った書類を、電子帳簿保存法に沿って保存するための、入力・訂正・保存の手順と担当を定める。

| 対象 | 内容 | 保存の方法 |
|---|---|---|
| 自社が作成する書類の控え | 見積書・納品書・請求書（システムで発行） | システムが、発行時の内容を固定して保存（版・ハッシュ・交付記録） |
| 送付した電子データ | お客様へ送ったPDF | システムの「送付PDF」＋ Box（別のメールで保存） |
| 受領した電子データ | メール等で受け取った請求書・注文書など | 【決定】**Box に統一**（システムの「受領書類」は使わない）（§6.1） |
| 紙で受け取った書類 | 納品書・請求書・領収書・注文書など | 【決定】**Box でスキャナ保存**。入力期間は受領後おおむね7営業日以内（§6.2） |

対象外: 会計帳簿（仕訳帳・総勘定元帳）。会計処理は顧問税理士が行う（システムは会計帳簿を持たない）。

## 2. 担当と権限

| 役割 | システムの権限 | 担当者 | 主な責任 |
|---|---|---|---|
| 責任者 | 管理者（admin） | 【決定】松田 | 設定・税率・振込先口座・スタッフの管理、取消の承認、システム変更の承認、点検の確認 |
| 入力担当 | 事務（office） | 【決定】事務員（仮: 関谷。正式に決まったら書き換える） | 案件・納品・請求・入金の入力、帳票の発行・送付・交付の記録、受領書類の登録 |
| 確認担当 | 事務または管理者 | 【決定】松田（責任者と兼任）。**松田が入力した場合は、松田が確認する**（入力した本人の確認になる。月次の点検（§9）で補う） | 発行前の内容確認、月次の点検 |
| 閲覧 | 閲覧のみ（viewer） | 【要決定】 | 見るだけ |
| 顧問税理士 | （Box／MFクラウドの管理者） | 顧問税理士 | 会計処理、帳簿との紐づけの確認 |

- アカウントは1人1つ。共用しない。退職・異動のときは、責任者がその日のうちに「有効」を外す（設定 → スタッフ）。
- 権限の割り当ては、責任者が決める。

## 3. 入力と発行の手順・期日（売上）

**【決定】の期日は確定、【案】は未決定です。**

| 手順 | 担当 | 期日（案） | システムでの操作 | 確認 |
|---|---|---|---|---|
| ① 見積の入力 | 入力担当 | 見積依頼の受領から【決定】**1週間以内** | 案件の登録、品目の入力、保存 | 右側の発行イメージで内容を確認 |
| ② 見積書の発行・送付 | 入力担当 | 入力後【当日】 | 見積書を発行（内容が固定される）→ 送付（§5） | 確認担当が金額・宛先を確認 |
| ③ 受注の登録 | 入力担当 | 注文の受領後【1営業日以内】 | 「受注にする」。客先注文番号を入力 | |
| ④ 納品の記録 | 入力担当 | 納品日から【決定】**3日以内** | 全数納品、または分納の記録 | 受注数との差異を確認 |
| ⑤ 納品書の発行・送付 | 入力担当 | 納品の記録後【当日】 | 納品書を発行 → 送付 | |
| ⑥ 請求書の作成・発行 | 入力担当 | 【決定】**5日以内**（締め日の翌日から数える。【要確認】）| 締め請求（または案件・納品ごと）→ 発行済みにする → 帳票の発行 → 送付 | 確認担当が、対象期間・内訳・合計・支払期日を確認 |
| ⑦ 入金の登録 | 入力担当 | 入金の確認後【決定】**3日以内** | 入金を登録（銀行・口座番号を入力）。消込は自動 | 未消込・残高を確認 |

- 金額・消費税の計算はシステムが行う。人が計算した金額を入力しない。
- 税率は、納品日の時点のものがシステムで固定される。税率の登録・変更は責任者のみ。
- 1枚の請求書に、請求済みの納品は入らない（二重請求の防止はシステムが行う）。

## 4. 訂正・取消の手順

- **データは削除しない。** 訂正は「取消」＋入れ直し（新しい版）で行い、取消した記録も残す。
- 取消には**理由の入力が必須**（システムが強制）。
- 取消の順序: 入金 → 請求書 → 納品（後ろの工程から。システムが、逆の順序を拒否する）。
- 発行済みの帳票（見積書・納品書・請求書）の訂正は、元データを直して**再発行**（新しい版）。**交付済みの旧版も、保存する**。
- 承認の方法【決定】: **ワークフロー**で行う。入力担当が**取消の承認を請求**し、**責任者（松田）が承認**してから、取消を実行する。システムに承認の機能は作らない【決定】。**運用で行う**: 責任者の了解を得て取消を実行し、**取消理由に承認者名（松田）を書く**。
- 手書きで加筆した書面を渡した場合は、その書面を紙で保存する（電子データの保存だけでは足りない）。
- データベースの管理画面や SQL で、帳票・納品・請求・入金を直接書き換え・削除しない（システムの固定内容の保護を迂回するため）。

## 5. 帳票の交付と保存

1. 帳票は、必ず**システムで発行（内容を固定）**してから、印刷・PDF化・送付する。画面を直接印刷しない。
2. 送付はPDFで行い、①お客様宛、②Box宛（別のメール。宛先は Box のアドレスだけ）の2通を、**同じPDF**で送る（操作マニュアル §5）。
3. 送付したら、同じ日に**交付を記録**する（方法・交付日・宛先）。郵送・手渡しも記録する。
4. 郵送・手渡しは、印刷して渡し、方法「紙」で記録する。

保存の内容: 発行時の内容（固定）、版、ハッシュ、交付記録、送付PDF、Box の保存。保存期間は§7。

## 6. 受領した書類の登録・保存

### 6.1 電子データで受け取ったもの
- **担当**: 入力担当。**期日**【決定】: 受領後おおむね**7営業日以内**。会社の事務の処理は**随時**のため、業務処理サイクル方式（最長2か月＋おおむね7営业日の例外）は使わない（2026-11-01 に決め直し）。
- 方法【決定】: **Box にアップロードする**（Box でタイムスタンプが自動で付く）。システムの「受領書類」には登録しない（二重に保存しない）。
- ファイルは、**受け取ったままのもの**を保存する（内容を打ち直したものは保存と認められない）。
- 検索のため、**取引年月日・取引先・取引金額**を入力する（Box の場合はファイル詳細に入力）。

### 6.2 紙で受け取ったもの（スキャナ保存）
【決定】**Box でスキャナ保存する**（入力期間は、受領後おおむね7営業日以内）。条件は次のとおり（Box の公式ガイド、国税庁の資料に基づく。`docs/電帳法対応方針.md` §4-3）。

| 項目 | 重要書類（契約書・納品書・請求書・領収書など） | 一般書類（見積書・注文書・検収書など） |
|---|---|---|
| 入力期間 | 受領後おおむね7営業日以内 | 制限なし（ただし読み取る際にタイムスタンプ） |
| 解像度 | 200dpi以上（スマホは約387万画素以上。標準カメラ撮影・メール添付・チャット経由は満たさない場合がある） | 同左 |
| 色 | カラー（24ビット） | グレースケール可 |
| 帳簿との紐づけ | 必要（Box のファイルIDを仕訳に残す、またはクラウド会計の証憑添付。税理士に確認） | 不要 |

- **期限（7営業日）を過ぎた重要書類は、紙の原本を保存する。**
- 過去分（スキャナ保存を始める前の書類）をスキャナ保存するには、届出書の提出が必要（令和5年7月パンフレット）。
- 業務処理サイクル方式（最長2か月＋おおむね7営業日）は**使わない**【決定】。事務は随時に処理し、7営業日以内に登録する。
- 紙の原本の廃棄【決定】: **原本とスキャンした画像を照合した後、決められた箱に入れて保管し、決算終了後に廃棄する**。入力期間を過ぎた重要書類は、廃棄せず、紙の原本として保存する。

### 6.4 規程
業務処理サイクル方式を使わないため、「各事務の処理に関する規程」は不要。スキャナ保存の手順は、**スキャナによる電子化保存規程（案）** `docs/事務処理規程_案.md` に定める（国税庁のサンプルとの照合と、税理士の確認がまだ。【要決定】【要確認】の項目あり）。
- 規程で定める内容: 受領の引継ぎ、読み取り（200dpi以上・カラー）、確認、Box へのアップロード、取引日・取引先・金額の入力、帳簿との紐づけ、紙の原本の扱い、点検

### 6.3 タイムスタンプ
- 総務大臣が認定する時刻認証業務のものを使う（`docs/タイムスタンプ事業者の比較.md`）。
- Box を使う場合は、Box のアップロードで自動付与される（Box のガイド）。システムで付与する場合は、**事業者と契約**し、設定の「このシステムで、タイムスタンプを付与する」をオンにする。**現在は未契約**。
- 付与待ち・期限超過は、月次の点検（§9）で確認する。

## 7. 保存期間と保存場所

| 項目 | 内容 |
|---|---|
| 保存期間 | 法人は**7年**。欠損金額が生じた事業年度（青色繰越欠損金等）は**10年**。起算日は確定申告書の提出期限の翌日。消費税のインボイス関連は7年（`docs/電帳法対応方針.md` §4-2） |
| 保存場所 | Supabase（クラウド。リージョンは【要決定】）、Box（MF クラウド） |
| 削除 | 保存期間中は削除しない（システムに削除機能はない）。保存期間後の廃棄は【要決定】 |
| バックアップ | 法令上の要件ではないが、7年以上の保存のため取る。保存先は【決定】**Google Drive**。方法（定期的なダンプ、暗号化、世代管理、復元の確認）は、Supabase のプロジェクトを作成してから設計する |

## 8. 見読可能装置・検索・ダウンロードの求め

- **見読可能装置**: PC、14インチ以上のカラーディスプレイ、カラープリンタ、操作マニュアルを、保存場所で使えるようにしておく。【設置場所】**現場事務所**（決定）。台数: 14インチ以上のカラーディスプレイとカラープリンタは**揃っている**【決定】
- **検索**: システムの「帳票」「受領書類」で、取引年月日・取引金額・取引先で検索できる（範囲指定、組合せ）。Box は、ファイル画面で検索する。
- **ダウンロードの求め（税務調査）**: システムの「出力」で、一覧CSVとファイル本体のZIPを出す（SHA-256の照合つき）。Box の分は、Box から出す。
- 税務職員から求められたら、責任者が対応する（【要決定】）。基準期間（2年前）の売上高が5,000万円以下の場合は、ダウンロードの求めに応じられることで、検索要件を満たせる（税理士に確認）。

## 9. 点検（月次）

責任者または確認担当が、**月の初めに**次を確認し、結果を **Google Drive** の点検表（点検日・点検者・結果・指摘）に記録する【決定】。

1. ダッシュボードの「未請求額」「未回収残高」「期日超過額」を確認する。
2. Box で、受領した書類に、**タイムスタンプが付与されていること**、**取引日・取引先・金額が入力されていること**、**重要書類の帳簿との紐づけ**を確認する。7営業日を過ぎた未登録の書類（受領日の記録と照合）がないかも確認する。
3. 納品の記録漏れ（受注システムの出荷との差異。「受注システムと同期」の結果の「ERPにだけある製番」「受注側にだけある製番」）を確認する。
4. 前月に取消した記録の理由・承認が書かれているかを確認する。
5. 「出力」で、ファイルのSHA-256の照合が一致していることを確認する（四半期に1回でよい。【案】）。

## 10. システムの管理・変更

- **アカウント**: 責任者が、Supabase の管理画面でユーザーを作成し、スタッフとして登録する。パスワードは他人と共有しない。
- **秘密情報**: Supabase の service_role キー、APIキー、受注GASのURL、パスワードは、**ソースにも書類にも書かない**。必要な人だけが持つ。
- **システムの変更**: ①変更の内容を決める → ②テスト（自動テスト）で確認 → ③責任者が承認 → ④反映。変更のたびに、`docs/システム概要書.md` の変更履歴と、関係する書類（仕様書・操作マニュアル・この書類）を同じ変更で更新する。
- **帳票のひな形を変えたとき**は、過去の控えの見た目が変わりうるため、変更履歴に記録する。
- **データの直接操作の禁止**: データベースの管理画面や SQL での、帳票・入金・納品・請求の書換え・削除は禁止（§4）。
